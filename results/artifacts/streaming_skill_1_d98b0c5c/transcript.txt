Async: up to **1,000** terms.\r\n\r\n**Contextual prompt â€” three levels of specificity** (use the least specific that covers your case):\r\n\r\n| Level | Length | Contains | Example |\r\n|-------|--------|----------|---------|\r\n| Domain | 2â€“5 words | The field only | `Medical consultation call.` |\r\n| Scenario | 5â€“15 words | What the call is about | `Cardiology consultation about chest pain symptoms.` |\r\n| Detailed | 20â€“50 words | Names, products, identifiers | `Cardiology consultation between Dr. Smith and a patient about recurring chest pain, ECG results, and hypertension medication.` |\r\n\r\n**Best practices:**\r\n- **Start with no `prompt` and no `keyterms_prompt`** â€” the model is optimized out of the box. Add context only for domain vocabulary it gets wrong, starting at the broadest level.\r\n- Write plain, complete sentences that *describe* the recording; keep it to one short block, not a keyword list (that's what `keyterms_prompt` is for).\r\n- Keyterms: use exact spelling/capitalization; avoid common words (over-inclusion causes overcorrection/hallucination).\r\n- Specify language via `language_code` (preferred) or by naming it in the prompt (e.g. \"Spanish customer support callâ€¦\").\r\n- Streaming: update both mid-session via `UpdateConfiguration`; a new keyterms array replaces the prior set, `[]` clears it.\r\n\r\n## Sync STT API (short-form audio, â‰¤120s)\r\n\r\nA separate synchronous endpoint for short clips â€” send audio in one HTTP request, get the transcript back in the response. **No polling, no transcript ID, no `upload` step.** Fully launched (GA) July 14, 2026 at real-time.45/hr. Ideal for voice-message transcription, short call recordings, or voice-agent pipelines that do their own turn detection and submit completed utterances.\r\n\r\n- **Endpoint:** `POST https://sync.assemblyai.com/v1/transcribe` (routes are versioned as of July 2026 â€” the unprefixed `/transcribe` still works for legacy clients, but new code should use `/v1/`). Global host routes to nearest region; use `sync.us.assemblyai.com` / `sync.eu.assemblyai.com` for data residency\r\n- **Required header:** `X-AAI-Model: universal-3-5-pro` (the only sync model in the SDKs; `u3-sync-pro` is a legacy accepted value)\r\n- **Auth:** `Authorization: YOUR_API_KEY` (Bearer prefix optional here, unlike the async REST API; or pass `?token=YOUR_API_KEY`)\r\n- **Body:** `multipart/form-data` with an `audio` part (`Content-Type: audio/wav` or `audio/pcm`) and an optional `config` JSON part\r\n- **`config` fields:** `prompt` (â‰¤4096 chars), `keyterms_prompt` (string[] â€” **renamed from `word_boost` in July 2026**; the aliases `word_boost` and `keyterms` are still accepted), `conversation_context` (string or string[] â€” prior conversation turns oldest-first, for continuity across a multi-turn conversation; oldest dropped when over the context budget), `language_codes` (ISO 639-1 list; singular `language_code` also accepted, default `en` â€” steers the default prompt toward the named language(s); **ignored when a custom `prompt` is set**), `timestamps` (bool, default `false` â€” **opt-in** per-word `start`/`end` in ms via forced alignment; omitted from the response if the aligner is unavailable, never estimated), and for `audio/pcm` also `sample_rate` + `channels` (required for raw PCM; WAV reads them from its header). **Unknown `config` fields are rejected with a 400** â€” don't pass async-API params here\r\n- **Audio limits:** 80msâ€“120s, â‰¤40MB, 16-bit only, mono/stereo (stereo down-mixed), sample rates 8000/16000/22050/24000/32000/44100/48000 Hz\r\n- **Response:** `{ text, words[{text, start?, end?, confidence}], confidence, audio_duration_ms, session_id, request_time_ms }` â€” word `start`/`end` (integer milliseconds) appear only when `timestamps: true`; only the clip-level durations carry the `_ms` suffix\r\n- **Pre-warming:** `GET https://sync.assemblyai.com/v1/warm` establishes the connection ahead of the first request (returns `200 {\"warm\":\"toasty\"}`). Python SDK: `SyncTranscriber.warm()` plus `aai.settings.keepalive_expiry` to hold the connection; Node SDK has `SyncTranscriber` too\r\n- **30s per-request deadline** (504 `inference_timeout`). For audio >120s use the async REST API; for live mic audio use Streaming. If you need the utterance **cleaned up or reshaped** (filler removed, formatted as a note) alongside the verbatim transcript, use the **Dictation API** below instead.\r\n\r\n```bash\r\ncurl -X POST https://sync.assemblyai.com/v1/transcribe \\\r\n  -H 'Authorization: YOUR_API_KEY' \\\r\n  -H 'X-AAI-Model: universal-3-5-pro' \\\r\n  -F 'audio=@sample.wav;type=audio/wav'\r\n```\r\n\r\n## Dictation API (short-form dictation, â‰¤120s, transcript + LLM rewrite)\r\n\r\nA **separate service** (own hostname, own request shape â€” not Sync, not Pre-recorded, not Streaming) for turning one spoken utterance into **send-ready text plus the verbatim transcript in a single HTTP call**. Cleanup runs **by default**: filler out, self-corrections resolved, punctuation/capitalization applied. Set `llm_instruction` for a different shape (bulleted action items, a clinical chart note, a booking confirmation). Runs on Universal-3.5 Pro across 32 languages. Use it for dictation apps, voice notes, scribes, and \"speak a message, send it\" flows; use Sync STT when you only want the verbatim transcript.\r\n\r\n- **Endpoint:** `POST https://dictation.assemblyai.com/v1/transcribe/live` (`/v1` only â€” no unversioned alias; `/v1/transcribe/stream` is the legacy path). `dictation.us.` / `dictation.eu.` for data residency\r\n- **Auth:** `Authorization: YOUR_API_KEY` (raw key, no Bearer)\r\n- **Body:** `multipart/form-data`, **`config` part first (required, JSON â€” send `{}` for defaults), then `audio`** (`audio/wav` or `audio/pcm`, â‰¤120s, 16-bit). The server transcribes as bytes arrive and can't start without the config, so audio-before-config or a missing config is a `400`. **Compressed formats (MP3/M4A/FLAC/OGG/WebM) â†’ `415`** â€” decode first\r\n- **`config` fields (exactly these; unknown â†’ `400`):** `sample_rate` + `channels` (required for raw PCM, ignored for WAV), `language_codes` (**a list**, default `[\"en\"]`, 32 codes), `stt_prompt` (â‰¤6000 chars, contextual *description* of the audio; alias `prompt` â€” send one, not both), `keyterms_prompt` (â‰¤100 terms / 8000 chars; aliases `keyterms`/`word_boost` accepted â€” send only one), `llm_instruction` (â‰¤2048 chars, plain-English rewrite task â€” **replaces** the default cleanup; omit/`null` keeps it). No `model`, `timestamps`, `conversation_context`, `speaker_labels`, `redact_pii`\r\n- **Response:** `{ text, words[{text, confidence}], confidence, llm_response, llm_error, audio_duration_ms, session_id, request_time_ms, sync_time_ms, auth_time_ms }`. `text` is always the verbatim transcript; the rewrite is in `llm_response`. **No word timestamps**\r\n- **The rewrite is best-effort:** a failed rewrite is still `200` with `llm_response: null` and `llm_error: \"timeout\"` (5s internal deadline) or `\"error\"`. **Fall back to `text`; never treat a non-null `llm_error` as a failed request.** SDKs expose this as `final_text`\r\n- **Upload while recording:** the body streams, so open the request when the user starts speaking and push PCM frames as captured (config first; don't go silent mid-body; a chunked body can't be replayed â€” keep audio in memory to retry)\r\n- **Pre-warming:** `GET https://dictation.assemblyai.com/warm` (unauthenticated, `200 {\"warm\":\"toasty\"}`; `/v1/warm` also works) â€” same client and same host as the transcription, shortly before it\r\n- **Errors:** two shapes â€” `{status, title, detail}` for most, `{error, error_code}` only for request-parsing failures; read `detail` then fall back to `error`. 429/502/503/504 transient; 400/413/415 fix the request; 401 fix the key. Client timeout 90s\r\n- **SDKs:** `DictationTranscriber` (Python **â‰¥1.5.2**, `assemblyai.dictation.v1`; install the current 1.6.1) and `client.dictation` (Node **â‰¥4.40.0**; install the current 4.41.5), both from Sept 11, 2026. Check the installed version before using the SDK path in an existing project; on an older SDK, call the endpoint over HTTP. See `references/dictation.md`\r\n\r\n```bash\r\ncurl -X POST https://dictation.assemblyai.com/v1/transcribe/live \\\r\n  -H 'Authorization: YOUR_API_KEY' \\\r\n  -F 'config={\"llm_instruction\": \"Turn this into a bulleted list of action items.\"};type=application/json' \\\r\n  -F 'audio=@sample.wav;type=audio/wav'\r\n```\r\n\r\n### Blurt (AssemblyAI's Mac dictation app)\r\n\r\n**Blurt** ([github.com/AssemblyAI/blurt](https://github.com/AssemblyAI/blurt)) is AssemblyAI's own free, open-source Mac dictation app, built on the Dictation API. Neither changes output formatting |\r\n| `prompt` is context, not instructions | Universal-3.5 Pro's `prompt` *describes* the audio (domain/scenario/details). Formatting or behavioral commands (punctuation rules, \"transcribe verbatim\", negative directives like \"don'tâ€¦\") are **not supported** and are ignored â€” transcription behavior is managed internally |\r\n| `summarization` / `auto_chapters` (top-level params) | **Deprecated.** Use **Speech Understanding** `summarization` (chaptered summary w/ timestamps + headlines) or `action_items` â€” `speech_understanding.request.<feature>` on `POST /v2/transcript` â€” or the LLM Gateway for fully custom prompts. **SDK caveat (Python 1.6.1 / Node 4.41.5):** both SDKs type `speech_understanding.request` with only `speaker_identification`/`translation`/`custom_formatting`. Python SDK â‰¥0.64.32 / Node â‰¥4.36.4 |\r\n| Check `Begin.configuration` | The `Begin` message echoes what the server applied: `configuration.{model, mode, api_version, speaker_labels, redact_pii, filter_profanity, domain, voice_focus}`. **Unknown or misspelled query params are ignored, not rejected**, so assert `configuration.model` equals the `speech_model` you asked for. Treat any non-letter label as unattributed.\n263\t- Per-word `speaker` may be absent on individual words even with diarization on. Fall back to the turn-level `speaker_label`.\n264\t- Accuracy improves over time within a session as the model accumulates more speaker data.\n265\t- Real-time labels can shift as more audio arrives â€” early turns in particular may be reassigned.\n266\t\n267\t### Speaker confidence (experimental)\n268\t\n269\tWith `speaker_labels` on, final `Turn` messages carry a turn-level `speaker_confidence` and each final word carries its own (every word in a sentence shares one value). Scores run 0.0â€“1.0 but are **not calibrated probabilities**, so compare them relatively (e.g. flag a turn's label as shaky vs the session's other turns) and don't use absolute thresholds. The word-level field is **omitted** when unavailable (normal on a session's first words), and a turn-level `0.0` means \"no score\", not \"wrong\". `SpeakerRevision` carries no confidences, so discard a stored score when a revision changes that turn's label. Neither SDK types this field; read it from the raw message.\n270\t\n271\t### Diarization turn-detection profile (Universal-3.6/3.5 Pro)\n272\t\n273\tEnabling `speaker_labels: true` **replaces the `mode` preset** with a dedicated diarization profile â€” `min_latency`/`balanced`/`max_accuracy` have **no effect** while diarization is on, and no warning is returned. The profile:\n274\t\n275\t- Caps turns at **10 seconds** (force-finalized; with `mode` presets the cap is 60s). A turn boundary is therefore **not** a speaker change â€” long monologues get split. Compare `speaker_label` across turns instead.\n276\t- Slows mid-turn partials from ~1s to **~3s** cadence; set `continuous_partials: true` to restore the ~1s cadence.\n277\t- Sets silence-before-turn-end defaults to **640ms min / 768ms max**, `vad_threshold` to 0.5, and `interruption_delay` to 500.\n278\t\n279\tExplicitly-supplied `min_turn_silence`, `max_turn_silence`, `max_turn_duration`, `vad_threshold`, and `interruption_delay` are applied **on top of** the profile â€” defaults shift, your overrides win. For voice-agent-grade latency with speaker labels, override the individual turn params rather than relying on `mode`.\n280\t\n281\t### Revised speaker labels (SpeakerRevision)\n282\t\n283\tWhen `speaker_labels` is enabled, the server runs a refinement pass over the whole conversation at session end and emits a final **`SpeakerRevision` message right before `Termination`** (after the client sends `Terminate`) when any label changed. Set **`speaker_labels_revision_interval_ms`** to also receive revisions **mid-session**. The minimum is 120000ms of audio time, recommended `300000` (intervals over 300000 may be clamped), the first arrives after ~2 minutes of audio, and one is sent only when some earlier label actually changed. SDK support: Python â‰¥1.6.1, Node â‰¥4.41.5.\n284\t\n285\t- Without the interval param: zero or one message, at session end. With it: possibly **many** messages.\n286\t- Each message is an **incremental delta**: a `revisions` array with **only the turns whose labels changed since the previous message**; unchanged turns are omitted and not re-sent. Apply messages **in arrival order; for a given `turn_order` the last one wins**.\n287\t- Each item: `turn_order` (matches the original `Turn`'s `turn_order`), `speaker_label` (corrected, string or null), and `words` (with corrected per-word `speaker`).\n288\t- **Text content and word timestamps are never changed** â€” only speaker assignments.\n289\t- The end-of-session pass adds approximately **400ms** of latency at session close; revisions never alter the real-time labels already delivered, so you apply them yourself.\n290\t- To apply: match each `turn_order` against the turn you already received and replace its `speaker_label` and per-word `speaker` values. Use the revised labels for the final, highest-quality transcript (persisting, post-call summaries, downstream LLMs).\n291\t\n292\t```json\n293\t{\n294\t  \"type\": \"SpeakerRevision\",\n295\t  \"revisions\": [\n296\t    {\n297\t      \"turn_order\": 3,\n298\t      \"speaker_label\": \"B\",\n299\t      \"words\": [\n300\t        { \"text\": \"Hello\",  \"start\": 1200, \"end\": 1450, \"speaker\": \"B\" },\n301\t        { \"text\": \"there.\", \"start\": 1450, \"end\": 1780, \"speaker\": \"B\" }\n302\t      ]\n303\t    }\n304\t  ]\n305\t}\n306\t```\n307\t\n308\t---\n309\t\n310\t## Context Carryover (Universal-3.6/3.5 Pro)\n311\t\n312\tUniversal-3.6 Pro and 3.5 Pro automatically carry prior **finalized** turns (`end_of_turn: true`) forward as context to improve accuracy on the next turn. New code should import from it â€” the path states which product and which API version you are pinned to:\n\n| Product | Import |\n|---------|--------|\n| Pre-recorded / async | `from assemblyai.prerecorded.v2 import Transcriber, AsyncTranscriber, Transcript, TranscriptionConfig` |\n| Sync STT (â‰¤120s) | `from assemblyai.sync.v1 import SyncTranscriber, AsyncSyncTranscriber, SyncTranscriptionConfig` |\n| Dictation (â‰¤120s, transcript + rewrite; SDK â‰¥1.5.2) | `from assemblyai.dictation.v1 import DictationTranscriber, AsyncDictationTranscriber, DictationConfig, DictationError` |\n| Streaming / realtime | `from assemblyai.streaming.v3 import RealTimeTranscriber, RealTimeTranscriberOptions, RealTimeParameters` |\n\nCross-cutting names are **not** re-exported by the subpackages â€” import `TranscriptStatus`, `TranscriptError`, `Settings`, `Client`, `AsyncClient`, and the global `settings` from the top-level package. Mixing both styles in one file is normal and expected.\n\nThe top-level `aai.Transcriber` / `aai.SyncTranscriber` and the flat module paths (`assemblyai.transcriber`, `assemblyai.sync`, `assemblyai.sync_api`) still work and are not deprecated â€” the examples below use `import assemblyai as aai` where it reads better.\n\n---\n\n## 1. Basic Transcription\n\n### From a URL\n\n```python\nfrom assemblyai import TranscriptStatus\nfrom assemblyai.prerecorded.v2 import Transcriber\n\ntranscriber = Transcriber(api_key=\"YOUR_API_KEY\")\ntranscript = transcriber.transcribe(\"https://example.com/audio.mp3\")\n\nif transcript.status == TranscriptStatus.error:\n    raise RuntimeError(f\"Transcription failed: {transcript.error}\")\n\nprint(transcript.text)\n```\n\n### From a local file\n\n```python\nimport pathlib\n\ntranscript = transcriber.transcribe(pathlib.Path(\"/path/to/local/audio.mp3\"))\n```\n\nThe SDK automatically uploads the local file to AssemblyAI's servers before transcription. No separate upload step is needed. `transcribe()` accepts a `pathlib.Path`, a `str` path, a URL, raw `bytes`/`bytearray`, or an open binary file â€” no `str()` wrapping needed for a `Path`.\n\n### Bounding the poll with `poll_timeout`\n\n`transcribe()` polls until the transcript reaches a terminal status, which by default means forever. Give it a deadline so a stuck job cannot hang a request handler:\n\n```python\nfrom assemblyai import TranscriptError\nfrom assemblyai.prerecorded.v2 import Transcriber\n\ntranscriber = Transcriber(api_key=\"YOUR_API_KEY\")\n\ntry:\n    transcript = transcriber.transcribe(\n        \"https://example.com/audio.mp3\",\n        poll_timeout=300,\n    )\nexcept TranscriptError as error:\n    # The job keeps processing server-side; the message carries the transcript id.\n    print(f\"still running: {error}\")\n```\n\nAvailable on `Transcriber.transcribe`, `Transcriber.transcribe_async`, and `AsyncTranscriber.transcribe`; omit it to keep the unbounded behavior. Pick the transcript up later with `Transcript.get_by_id(transcript_id)`.\n\n### With TranscriptionConfig and speech_models fallback\n\nUse `speech_models` to specify a preferred model with automatic fallback:\n\n```python\nconfig = aai.TranscriptionConfig(\n    speech_models=[\"universal-3-5-pro\", \"universal-2\"]\n)\n\ntranscriber = aai.Transcriber(config=config)\ntranscript = transcriber.transcribe(\"https://example.com/audio.mp3\")\nprint(transcript.text)\n```\n\nIf the first model in the list cannot process the audio, the next model is used as a fallback.\n\n---\n\n## 2. Use Speech Understanding summarization instead. **Don't pass it through `TranscriptionConfig(speech_understanding=...)`.** The SDK's typed model (`SpeechUnderstandingFeatureRequests`, still true as of 1.6.1) only knows `speaker_identification`, `translation`, and `custom_formatting`, so `summarization` and `action_items` are **silently dropped**: the API then rejects the request with `speech_understanding.request is empty`, and the SDK's `Transcript` wouldn't expose the result anyway. Send the request over REST instead:\n\n```python\nimport time\n\nimport requests\n\nAPI_KEY = \"YOUR_API_KEY\"\nBASE = \"https://api.assemblyai.com/v2/transcript\"\nheaders = {\"Authorization\": API_KEY}\n\njob = requests.post(\n    BASE,\n    headers=headers,\n    json={\n        \"audio_url\": \"https://example.com/audio.mp3\",\n        \"speaker_labels\": True,\n        \"speech_understanding\": {\n            \"request\": {\n                \"summarization\": {\"summary_type\": \"bullets\", \"effort\": \"low\"},  # summary_type is required\n                \"action_items\": {\"effort\": \"low\"},\n            }\n        },\n    },\n)\njob.raise_for_status()\ntranscript_id = job.json()[\"id\"]\n\nwhile True:\n    transcript = requests.get(f\"{BASE}/{transcript_id}\", headers=headers).json()\n    if transcript[\"status\"] in (\"completed\", \"error\"):\n        break\n    time.sleep(3)\n\nresponse = transcript.get(\"speech_understanding\", {}).get(\"response\", {})\nsummary = response.get(\"summarization\", {})\nprint(summary.get(\"block_summary\"))\nfor chapter in summary.get(\"summary\", []):\n    print(chapter[\"headline\"], chapter.get(\"bullets\") or chapter.get(\"text\"))\nfor item in response.get(\"action_items\", {}).get(\"items\", []):\n    print(item[\"action_item\"])\n```\n\nThe SDK works for `speaker_identification`, `translation`, and `custom_formatting` (typed request models in `aai.types`). For fully custom summaries, use the LLM Gateway (section 9).\n\n> **Note:** `summarization` and `auto_chapters` are mutually exclusive. Do not enable both in the same config.\n\n### Auto Highlights (Key Phrases)\n\n```python\nconfig = aai.TranscriptionConfig(auto_highlights=True)\ntranscript = transcriber.transcribe(\"https://example.com/audio.mp3\", config=config)\n\nfor result in transcript.auto_highlights.results:\n    print(f\"{result.text} (count: {result.count}, rank: {result.rank:.4f})\")\n```\n\n---\n\n## 6. Prompting with Universal-3.5 Pro\n\n`prompt` and `keyterms_prompt` are **complementary** â€” use either, or both together. `prompt` is a contextual *description* of the audio (domain â†’ scenario â†’ full detail), **not** formatting/behavioral instructions (those are ignored). `keyterms_prompt` is an explicit list of terms to boost (up to 1,000 for async). Start with neither and add only for vocabulary the model gets wrong.\n\n```python\nconfig = aai.TranscriptionConfig(\n    speech_models=[\"universal-3-5-pro\"],\n    prompt=\"Cardiology consultation about chest pain symptoms.\",\n    keyterms_prompt=[\"Dr. Smith\", \"ECG\", \"hypertension\"],\n)\n\ntranscript = aai.Transcriber().transcribe(\"https://example.com/audio.mp3\", config)\nprint(transcript.text)\n```\n\n> **Note on disfluencies:** Enable `disfluencies=True` to keep \"ums\" and \"uhs\" in the transcript.\n\n---\n\n## 8. Streaming v3 (Realtime)\n\nUse `assemblyai.streaming.v3` for new realtime STT code. In 1.x the classes are named `RealTime*` â€” `RealTimeTranscriber`, `RealTimeTranscriberOptions`, `RealTimeParameters`, `RealTimeEvents`, `RealTimeError`. The former `Streaming*` names are still bound to the same objects (so `isinstance` checks and old imports keep working), but write the `RealTime*` names.\n\nSet `speech_model=\"universal-3-6-pro\"` explicitly. The SDK sends no model when you omit it, so the server default applies (currently `universal-3-6-pro`), but pinning it keeps behavior deterministic. The enum validates locally: `universal-3-6-pro` needs **â‰¥1.1.0**. `sample_rate` is required for PCM encodings and optional for the self-describing compressed ones (`opus`, `ogg_opus`, `aac`).\n\n```python\nfrom assemblyai.streaming.v3 import RealTimeParameters, RealTimeTranscriber\n\ntranscriber = RealTimeTranscriber(api_key=\"YOUR_API_KEY\")\n\ntranscriber.connect(\n    RealTimeParameters(\n        speech_model=\"universal-3-6-pro\",\n        sample_rate=16_000,\n    )\n)\n\n# `chunks` is any iterable of 16-bit PCM frames from your capture library.\nchunks = [b\"\\x00\\x00\" * 160]\ntranscriber.stream(chunks)\n\ntranscriber.disconnect(terminate=True)\n```\n\n`api_key=` on the constructor covers the common case; pass `RealTimeTranscriberOptions` when you need more â€” `api_host`, `token` (a temporary token instead of a key), `connect_timeout`, `max_connection_retries`, `connection_retry_delay`, `terminate_timeout`.\n\n**The SDK does not capture microphone audio.** `assemblyai.extras` and its `MicrophoneStream` were removed in 1.0.0, along with the `[extras]` install option. Bring your own capture â€” `pyaudio`, `sounddevice`, a loopback device, a file â€” and pass 16-bit PCM chunks to `stream()`.\n\nFor the async client, use `AsyncRealTimeTranscriber` (formerly `AsyncStreamingClient`) from the same module.\n\n**Mid-stream updates** go through `set_params()` with a `RealTimeSessionParameters`. There is no `update_configuration()` method, whatever some docs snippets show:\n\n```python\nfrom assemblyai.streaming.v3 import RealTimeSessionParameters, RealTimeTranscriber\n\ntranscriber = RealTimeTranscriber(api_key=\"YOUR_API_KEY\")\n\n# e.g. the agent just asked for a phone number: hold the turn open longer\ntranscriber.set_params(RealTimeSessionParameters(min_turn_silence=1000))\n\n# feed the agent's spoken reply back as context for the next user turn\ntranscriber.set_params(RealTimeSessionParameters(agent_context=\"What's your callback number?\"))\n```\n\n`RealTimeSessionParameters` covers `min_turn_silence`, `max_turn_silence`, `vad_threshold`, `keyterms_prompt`, `prompt`, `agent_context`, `interruption_delay`, `language_codes`, `filter_profanity`, `session_heartbeat` (plus `end_of_turn_confidence_threshold` / `format_turns` for Universal Streaming). `filter_profanity` is also in the model, but set it at connect time. It has **no `mode` field**, and unknown fields are silently dropped, so to switch `mode` mid-stream you need the raw WebSocket `UpdateConfiguration` message.\n\n**SDK gaps to know about (1.6.1):**\n- `previous_context_n_turns` isn't a `RealTimeParameters` field and gets dropped silently. Leave it at the server default or use the raw WebSocket.\n- `TurnEvent` has no `utterance` or `speaker_confidence`, and `Word` has no `speaker_confidence`. Pydantic drops those fields on parse.\n- `BeginEvent.configuration` is typed with `model`, `mode`, and `api_version` only. Check `event.configuration.model` to confirm which model you got.\n- With `speaker_labels=True`, register `RealTimeEvents.SpeakerRevision` to receive `SpeakerRevisionEvent` (`revisions[{turn_order, speaker_label, words}]`). `speaker_labels_revision_interval_ms` (1.6.1+) adds mid-session revisions on top of the final one.\n\n---\n\n## 9. LLM Gateway Usage from Python\n\nThe LLM Gateway provides access to LLMs via AssemblyAI's infrastructure. Use `requests` to call the gateway endpoint directly. **Do not use LeMUR â€” it is deprecated.**\n\n```python\nimport requests\n\nAPI_KEY = \"YOUR_API_KEY\"\n\nresponse = requests.post(\n    \"https://llm-gateway.assemblyai.com/v1/chat/completions\",\n    headers={\n        \"Authorization\": API_KEY,\n        \"Content-Type\": \"application/json\",\n    },\n    json={\n        \"model\": \"claude-sonnet-4-6\",\n        \"messages\": [\n            {\n                \"role\": \"user\",\n                \"content\": \"Summarize the key themes from this transcript: ...\",\n            }\n        ],\n        \"temperature\": 0.5,\n    },\n)\n\nresult = response.json()\nprint(result[\"choices\"][0][\"message\"][\"content\"])\n```\n\nThe gateway follows the OpenAI-compatible chat completions format. The `Authorization` header uses the API key directly â€” no Bearer prefix.\n\n---\n\n## 10. Sync STT (Short-Form Audio, â‰¤120s)\n\n`SyncTranscriber` (`assemblyai.sync.v1`) wraps the Sync STT API â€” one HTTP round trip, no polling. Call `warm()` shortly before transcribing to pre-establish the connection (it's idempotent and cheap), and set `keepalive_expiry` to hold the pooled connection between requests (useful in voice-agent pipelines):\n\n```python\nimport assemblyai as aai\n\naai.settings.api_key = \"YOUR_API_KEY\"\naai.settings.keepalive_expiry = 30  # seconds to keep the connection alive between requests\n\ntranscriber = aai.SyncTranscriber()\ntranscriber.warm()  # optional: pre-warm so transcribe() reuses the open connection\n\nresult = transcriber.transcribe(\n    \"/path/to/local/recording.wav\",\n    config=aai.SyncTranscriptionConfig(\n        prompt=\"Customer voice message about an online order.\",\n        keyterms_prompt=[\"AssemblyAI\"],\n        timestamps=True,  # opt-in word-level start/end (ms)\n    ),\n)\nprint(result.text)\n```\n\nAccepts a local file path, raw bytes, or a stream â€” **not a URL**. There is also `transcribe_async()` and `close()`, and `AsyncSyncTranscriber` (added in 1.0.0) for asyncio callers, with an awaitable `warm()`. The model defaults to `universal-3-5-pro` (the only sync model in the SDK). `SyncTranscriptionConfig` fields mirror the REST `config` part: `model`, `prompt`, `keyterms_prompt`, `conversation_context`, `language_codes`, `timestamps`, and `sample_rate`/`channels` for raw PCM. See `references/api-reference.md` Â§16 for limits and error codes.\n\n---\n\n## 12. Dictation (Short-Form Dictation, â‰¤120s, Transcript + Rewrite)\n\n`DictationTranscriber` (`assemblyai.dictation.v1`, also `aai.DictationTranscriber`) wraps the **Dictation API** (`dictation.assemblyai.com`) â€” a separate service from Sync STT that returns the verbatim transcript **and** an LLM-cleaned, send-ready rewrite in one call. Cleanup runs by default; `llm_instruction` asks for a different shape.\n\n**Version gate:** added in **1.5.2** (Sept 11, 2026); install the current **1.6.1**. Anything older (e.g. 1.3.0) has no `DictationTranscriber` â€” check `pip show assemblyai` in an existing project and fall back to the raw HTTP example in `references/dictation.md` if it can't upgrade yet.\n\n```python\nimport assemblyai as aai\nfrom assemblyai.dictation.v1 import DictationConfig, DictationTranscriber\n\naai.settings.api_key = \"YOUR_API_KEY\"\naai.settings.keepalive_expiry = 30  # keep the warmed connection through the recording\n\nconfig = DictationConfig(\n    stt_prompt=\"A doctor dictating a patient visit note.\",  # context, not instructions (â‰¤6000 chars)\n    keyterms_prompt=[\"amoxicillin\", \"lisinopril\", \"metoprolol\"],  # â‰¤100 terms / 8000 chars\n    llm_instruction=\"Remove filler words and rewrite as a concise clinical chart note.\",  # â‰¤2048 chars\n)\n\nwith DictationTranscriber() as transcriber:\n    transcriber.warm()  # optional: as soon as you know audio is coming\n    result = transcriber.transcribe_live(\"/path/to/local/recording.wav\", config)\n\nprint(result.text)        # verbatim transcript â€” never altered by the LLM\nprint(result.llm_response)  # the rewrite, or None if the best-effort rewrite failed\nprint(result.final_text)  # llm_response, falling back to text\n```\n\n- `transcribe_live(data, config=None)` takes a local path, raw bytes, a binary file object, **or an iterator of PCM chunks** â€” the request starts immediately and uploads as you produce, so most of the utterance is uploaded by the time the speaker stops. **Not a URL** (`ValueError`).\n- `open_live(config=None)` is the **push-style** counterpart for callback-driven sources (a mic library, a WebRTC track, a telephony stream): returns a `DictationLiveSession` â€” `session.write(chunk)` from any thread (never blocks), `session.close()` ends the audio, `session.result()` returns the `DictationResponse`, `session.abort()` drops the request. As a context manager, a clean exit closes and an exception aborts.\n- **Raw PCM** needs `sample_rate` **and** `channels` on `DictationConfig` (setting either marks the audio as `audio/pcm`; leave both unset for WAV). Compressed formats are rejected by the service with `415`.\n- `DictationConfig` is `extra=\"forbid\"` and validates the caps client-side: `sample_rate`, `channels`, `language_codes` (a list, e.g. `[\"es\"]`), `stt_prompt`, `keyterms_prompt` (whitespace stripped, empties dropped), `llm_instruction`. **No** `model`, `prompt`, `timestamps`, or `conversation_context` â€” those are `SyncTranscriptionConfig`.\n- `DictationResponse.final_text` is a property: `llm_response` when present, else `text`. Never treat a non-`None` `llm_error` (`\"timeout\"` / `\"error\"`) as a failed request.\n- Failures raise `DictationError` (`status_code`, `error_code`, `retry_after` â€” seconds from `Retry-After` on 429/503, `None` when absent). Constructor takes `api_key=`, `client=`, a default `config=`, and `max_workers=` (thread pool for `open_live` sessions).\n- Settings: `aai.settings.dictation_base_url` (default `https://dictation.assemblyai.com`; set `dictation.us.` / `dictation.eu.` for residency) and `aai.settings.dictation_http_timeout` (300s, per socket operation).\n- `AsyncDictationTranscriber` has the same surface (`await transcribe_live(...)`, `open_live(...)` â†’ `AsyncDictationLiveSession`, awaitable `warm()`); `asyncio.create_task(transcriber.warm())` overlaps the handshake with the recording.\n\n```python\nimport assemblyai as aai\nimport sounddevice as sd\n\naai.settings.api_key = \"YOUR_API_KEY\"\nconfig = aai.DictationConfig(sample_rate=16000, channels=1)  # raw PCM: both required\n\nwith aai.DictationTranscriber() as transcriber:\n    with transcriber.open_live(config) as session:\n        stream = sd.RawInputStream(\n            samplerate=16000, channels=1, dtype=\"int16\",\n            callback=lambda data, *_: session.write(bytes(data)),\n        )\n        with stream:\n            input(\"Dictating, press Enter to stop... \")\n    print(session.result().final_text)\n```\n\nSee `references/dictation.md` for the endpoint, config limits, error shapes, and the raw-HTTP fallback.\n\n---\n\n## 13. Asyncio Support\n\nEvery product has an asyncio transcriber: `AsyncTranscriber` (`prerecorded.v2`), `AsyncSyncTranscriber` (`sync.v1`), `AsyncDictationTranscriber` (`dictation.v1`, â‰¥1.5.2), and `AsyncRealTimeTranscriber` (`streaming.v3`).\n\nThe async HTTP transcribers hold a connection pool, so use them as async context managers and the pool is always released:\n\n```python\nimport asyncio\n\nfrom assemblyai.prerecorded.v2 import AsyncTranscriber\n\n\nasync def main():\n    async with AsyncTranscriber(api_key=\"YOUR_API_KEY\") as transcriber:\n        transcript = await transcriber.transcribe(\n            \"https://example.com/audio.mp3\",\n            poll_timeout=300,\n        )\n        print(transcript.text)\n\n\nasyncio.run(main())\n```\n\n`aclose()` is the explicit equivalent. A client you pass in with `client=` stays yours to close; anything the transcriber builds itself â€” including a client derived because you also passed `api_key=` â€” it closes itself.\n\n---\n\n## 14. Migrating from 0.x to 1.x\n\nMost 0.x code runs on 1.x unchanged. No method signature was narrowed, every argument that worked in 0.x still works, and the new ones are optional keywords.
